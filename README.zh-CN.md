# PHP 站点部署包与增量发布

[English](README.md) | [简体中文](README.zh-CN.md)

> 把「静态前端 + 原生 PHP 接口」的站点打成一个可直接上传的包，上传前先用本机真实 PHP 引擎原样跑一遍。

## 这是什么

> **脱敏说明。** 本 README 已经写成通用版本。技能文件本身可能仍带有内部域名、主机名或本机绝对路径。发布前请先跑一遍扫描（见 `opensource-preflight-audit`），把命中的内容替换掉。

这不只是打个压缩包。这个技能围绕一个很具体的失败来做：本地一切正常，因为静态文件是用开发服务器起的；一上传才发现，PHP 那一半根本没跑起来过。

解法是让包在上传之前就可运行：先在本地用真实 PHP 引擎把这份包原样跑一遍，然后才传。

## 为什么开源

这类站点我们经常部署 —— 一个静态前端，后面挂几个 PHP 接口。本地通过、服务器失败这个落差，自动化掉之前吃掉过我们好几个晚上。

它是一套部署流程，不是产品。里面没有我们的东西。

## 能做什么

- **先打包，再本地跑一遍。** 上传之前，用真实 PHP 引擎把这份包执行一次，让本地和服务器的落差在代价还小的时候就暴露出来。
- **增量发布器。** 站点上线之后，后续更新只同步改动过的部分，不整体重传。
- **一份完整的建站清单。** 子域名创建、DNS 记录、证书签发、文件传输，按该做的顺序排好。
- **上传后核验。** 不把"传完了"当成"站点正常"。 

## 环境要求

Windows · PHP · Python 3

## 安装

```bash
git clone https://github.com/<你的用户名>/php-site-deploy-package.git
```

然后把整个目录放进技能目录：

| 系统 | 路径 |
|---|---|
| Windows | `C:\Users\<你>\.workbuddy\skills\php-site-deploy-package\` |
| macOS / Linux | `~/.workbuddy/skills/php-site-deploy-package/` |

没有构建步骤，重启对话即生效。

## 怎么用

直接说要做部署：

- "把这个打包，上传前先检查一下"
- "把这次的改动部署到线上"
- "从零建一个子域名"

它会构建、本地验证、上传，然后在服务器上确认。

## 注意与边界

1. **本地开发服务器不执行 PHP。** 静态文件能正常打开，不能证明 PHP 那一半任何事。本地执行那一步就是为这个存在的。
2. **增量发布需要干净基线。** 如果线上已经和打包版本脱节，先做一次全量发布。
3. **证书和 DNS 要时间生效。** 清单把顺序排好，就是为了不让你卡在一条本该更早创建的记录上。
4. **发布前备份。** 增量发布器缩小的是影响范围，不是取消备份的必要性。
